Does Query-Portfolio Diversification Predict a Page's Resilience to Visibility Decline?

Moulendra Balaji · August 2026 · FlyRank ML Internship

Abstract. Content pages that depend on a narrow set of search queries are intuitively more fragile — but does the data bear this out? We construct a query-concentration signal (Herfindahl-Hirschman Index over a page's query portfolio) from 17 months of pseudonymized warehouse data (~79M daily-performance rows, ~2.4M query-level observations) and test whether it predicts forward visibility decline. Using a page-grouped, time-aware train/test split to prevent label leakage, we compare a trend-continuation baseline, logistic regression, and gradient-boosted trees. The concentration signal is independently associated with decline risk (observed), the gradient-boosted model achieves an AUC of 0.66 on the held-out test set (directional), and the model's top-50 precision of 0.69 meaningfully exceeds the baseline's 0.56 (decision-support). No claim of causation is made — the findings identify pages whose query portfolio structure makes them worth reviewing first, not pages where a specific intervention is guaranteed to work.

1 Introduction

When a content page earns search visibility from a single dominant query — say, one branded how-to term — the loss of that ranking position can collapse the page's traffic overnight. Pages whose visibility is spread across dozens of queries are, intuitively, more resilient: losing one query's ranking is a scratch, not a wound. But intuition is not evidence, and the SEO industry lacks a quantified answer to a simple question: does query-portfolio concentration predict which pages will decline?

This paper tests that question. We build a concentration metric — the Herfindahl-Hirschman Index (HHI), borrowed from antitrust economics — over each page's query portfolio, and ask whether it forecasts forward visibility decline after controlling for momentum, position, and content-age signals. We frame the problem as a ranking task (which pages should an editor review first?), not a binary classification, because the real-world output is a prioritized queue under constrained human capacity.

Observed We study ~519K pseudonymized content pages across ~100 clients over 17 months of daily search-performance data. Directional A page-grouped, time-aware split ensures that no page appears in both training and test sets, and that training data strictly precedes test data chronologically. Decision-support The output is a ranked queue with reason codes — an ordering a human reviews, not an automated verdict.

Why this matters

Content teams operate under tight resource constraints. An editor at a mid-size site might review 20–50 pages per week. Sending that editor to the wrong 50 pages — pages that are declining for reasons a refresh cannot address, or pages that were never at risk — wastes the most valuable resource: attention. A signal that identifies pages whose portfolio structure makes them fragile gives editors a new lens for triage, one that complement existing momentum-based flags.

Time windows

Features are computed from January–March 2026 (the feature window). The forward-label is measured in April 2026 (the label window). The decision moment is April 1 — an editor reviews the queue using only what January–March showed. The query table's fixed 90-day window is carefully aligned: only portfolio-composition columns (HHI, breadth, top-1 share) are used, never the table's own *_last30 aggregates which would overlap the label period.

Exclusions

Observed We exclude: (a) pages with fewer than 100 March impressions (insufficient demand to justify editor time), (b) GA4 columns before ga4_data_available = TRUE (zeros there are instrument absence, not zero engagement), (c) the fact_content_query_90d table's time-aggregated columns (impressions_last30, etc.) which overlap the label window, and (d) June 2026 (the sealed final-month partition used only for sample iteration, never label development).

3 Methodology

3.1 Features

We construct 14 features across three categories. All are computable from data available at the decision moment (April 1).

3.2 Label

Observed forward_decline = 1 if April impressions are < 80% of March impressions, for pages with ≥ 100 March impressions. The base rate is approximately 38.7%. We also compute forward_pct_change as a continuous variant for regression analysis.

3.3 Baseline: trend-continuation

The baseline encodes the simplest possible rule: if a page's trailing impression slope is negative, predict decline; otherwise predict stability. This is the "naive trend-continuation" comparator — it captures momentum-only reasoning without any portfolio signal.

3.4 Models

Logistic Regression (scaled, L2-regularized) provides a linear baseline and interpretable coefficients. Gradient-Boosted Trees (LightGBM, 200 estimators, max depth 5, learning rate 0.05) capture non-linear interactions between concentration, position, and momentum features. Both are evaluated on the same held-out test set with the same metrics.

3.5 Split design

Directional The split is time-aware: training data comes from pages whose feature windows end before the final two months; validation uses the second-to-last month; test uses the last month. This prevents any page from appearing in both training and test, and prevents temporal leakage (features from the future leaking into training).

3.6 Leakage controls

The following columns are never used as features: trend_direction, trend_pct, is_declining_label (these encode the label or its proxy). The fact_content_query_90d table's *_last30 aggregates are excluded because their 90-day window overlaps the label period for a mid-panel decision point. A suspect-feature test confirms that adding any of these columns causes an anomalous AUC jump (the leakage fingerprint).

The lift from trend-only to LightGBM at Precision@50 is 0.56 → 0.69 (a 23% relative improvement). At Precision@20 the gap is wider: 0.55 → 0.70 (27% relative). The baseline performs only modestly above the base rate (0.387), confirming that momentum alone is a weak signal for this task.

4.2 Feature importance

Directional The LightGBM model's top features by importance are: trailing_trend_slope (momentum), query_hhi (concentration), pos_volatility, top1_dependency, and ctr_vs_position_expected. The concentration signal (HHI) ranks as the second-most-important feature — it carries independent information beyond what momentum alone provides.

4.3 Concentration and decline: the raw relationship

Observed Before modeling, we verify the raw association. Pages with high concentration (query_hhi > 0.5) decline at a rate of 45.2%, versus 33.8% for low-concentration pages — a 11.4 percentage-point gap in the observed data. This gap persists across position tiers and content-age buckets, though it narrows for very high-traffic pages (≥10K impressions) where baseline visibility provides a buffer.

4.4 Error analysis

Directional The model's most confident false positives (predicted decline, but page was stable) tend to be pages with high concentration but very high absolute impression volume — the "too big to fail" portfolio where sheer traffic provides resilience despite narrow query dependence. The false negatives (predicted stable, but page declined) are often pages with moderate concentration but severe position slippage — the momentum signal was too weak to flag, but a rank drop in a key query drove the decline. Both error patterns suggest natural extensions: an interaction term between concentration and volume, and a richer position-dynamics feature.

4.5 Comparison against the baseline

Decision-support The trend-continuation baseline achieves Precision@50 of 0.56, only modestly above the 0.387 base rate. This confirms that "momentum alone" is a weak signal for the editor's triage decision. The LightGBM model improves this to 0.69 — meaning that of the top 50 pages the model flags for review, roughly 35 are genuine decline-with-demand cases, versus 28 from the trend baseline. That is 7 more productive edits per 50-page batch, a meaningful improvement for a resource-constrained team.

5 Limitations

Observed This study has several limitations that constrain the strength of its claims:

Observational design. The data is cross-sectional and retrospective. We observe associations between portfolio concentration and decline, but we cannot establish that diversification causes resilience, nor that concentrating queries causes fragility. Confounding factors (content quality, competitor actions, algorithm changes) are not controlled for. Any causal claim would require a controlled experiment or matched design that this dataset does not support.

Directional Single-market generalizability. The dataset covers pseudonymized content from FlyRank's client portfolio. The concentration-decline relationship may differ for sites with different content strategies, audience geographies, or search verticals. We report the association as observed in this dataset; transfer to other portfolios is a hypothesis, not a finding.

Directional Query table window alignment. The fact_content_query_90d table provides a fixed 90-day window. For pages at the edge of the panel, this window may not align perfectly with the feature window. We mitigate this by using only portfolio-composition columns (HHI, breadth) and excluding time-aggregated columns, but some misalignment is inevitable.

Decision-support Proxy label. forward_decline flags pages that lost >20% of impressions month-over-month. This is a proxy for "visibility decline" — it does not capture gradual erosion below the threshold, nor does it distinguish between declines caused by content decay versus those caused by competitor improvements or algorithm shifts. The label is a pragmatic threshold, not a ground-truth definition of the underlying construct.

Observed Model performance ceiling. The best AUC of 0.66 is moderate. The features available in this dataset (structural and performance metrics, no content text or keyword semantics) leave substantial variance unexplained. The model is useful as a triage tool but not as a definitive classifier.

Decision-support No content-text signals. The dataset contains no raw text, titles, or keyword data — only pseudonymized hashes. A model that could assess semantic freshness, intent alignment, or topical depth might substantially outperform the structural features used here. This is a data limitation, not a methodological one.

To rerun

1. Clone this repository.
2. Request access to FlyRank/internship-warehouse (instant approval).
3. Set HF_TOKEN as an environment variable or in a .env file at the repo root.
4. Run pip install -r requirements.txt.
5. Open any notebook in Jupyter/Colab and run all cells.

Random seeds

All models use random_state=42 (scikit-learn) or seed=42 (LightGBM). Results are deterministic within the same library versions; minor variation (±2 AUC points) is expected across different scikit-learn/LightGBM versions.

Environment

Python 3.11+, pandas ≥ 2.2, scikit-learn ≥ 1.4, LightGBM ≥ 4.0, DuckDB ≥ 1.0, huggingface_hub ≥ 0.24, matplotlib ≥ 3.8.
